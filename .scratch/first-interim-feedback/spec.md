# Spec: 1차 중간 피드백 — 검색 중심 홈, 고객 모바일, 직원 진입

Status: ready-for-agent

## Problem Statement

고객이 루트로 접속하면 브랜드 소개를 먼저 보고 도서 검색으로 이동해야 한다. 매장에서 주로 사용하는 모바일 화면은 일부 반응형 처리가 있어도 고객의 검색·결과 확인·도서 입고 신청 흐름을 끝까지 검증하지 못했다. 고객 화면의 직원 로그인 링크는 불필요하게 직원 운영 화면의 입구를 노출하고, 직원이 이미 로그인했어도 직원 진입 화면에서 세션을 확인하지 않아 다시 로그인해야 하는 것처럼 보인다.

## Solution

루트는 도서 검색 중심 Home으로 제공하고 기존 브랜드·시설 콘텐츠는 매장 소개로 이동한다. 고객 탐색은 검색 중심 Home, 매장 소개, 즐길거리, 메뉴·요금, 이벤트·공지, 매장 안내로 구성한다. 고객 화면 전체에서 좁은 화면의 검색과 도서 입고 신청을 완결할 수 있게 한다.

직원 로그인 링크는 고객 화면에서 제거한다. 로고를 3초간 길게 누르면 저장된 유효 세션과 승인 상태를 확인해 승인된 직원은 대시보드로, 나머지는 직원 로그인으로 보낸다. 직원용 직접 주소는 유지하고 같은 권한 검사를 적용한다. 매장 전용 PC와 직원 개인 기기에서는 세션을 복원하고, 명시적 로그아웃을 제공한다.

## User Stories

1. As a 고객, I want `/`에서 바로 도서 검색을 시작할 수 있어, 브랜드 소개를 지나치지 않고 도서 재고를 찾을 수 있다.
2. As a 고객, I want 로고를 일반 클릭하면 검색 Home으로 돌아가, 어느 고객 화면에서도 검색을 다시 시작할 수 있다.
3. As a 고객, I want 매장 소개에서 브랜드 비주얼, 4대 포인트와 시설 정보를 볼 수 있어, 검색과 매장 정보를 목적에 맞게 찾을 수 있다.
4. As a 고객, I want 기존 `/books`와 `/search` 주소도 검색으로 열려, 저장한 링크와 검색 결과가 계속 유효하다.
5. As a 모바일 고객, I want 고객 화면에서 가로 스크롤과 주요 조작의 잘림 없이 탐색할 수 있다.
6. As a 모바일 고객, I want 검색 결과의 도서명, 보유 권수와 서가 위치를 읽을 수 있어, 직원에게 묻지 않고 책을 찾을 수 있다.
7. As a 모바일 고객, I want 화면 키보드가 열려도 검색과 도서 입고 신청을 완료할 수 있다.
8. As a 고객, I want 공개 화면에서 직원 로그인 버튼을 보지 않아, 고객 탐색에 운영 기능이 섞이지 않는다.
9. As a 직원, I want 브랜드 로고를 3초간 길게 눌러 직원 진입을 시작할 수 있다.
10. As an 승인된 직원, I want 저장된 유효 세션으로 직원 진입 시 대시보드로 바로 이동해, 매번 로그인하지 않는다.
11. As a 미로그인·대기·비활성화 사용자, I want 직원 진입 시 로그인 또는 접근 거부 상태를 보게 되어, 승인된 Staff만 운영 화면을 사용한다.
12. As a 직원, I want 직접 주소나 북마크로도 동일한 권한 검사를 거쳐 직원 화면에 들어갈 수 있다.
13. As a 직원, I want 명시적으로 로그아웃할 수 있어, 기기에서 운영 세션을 종료할 수 있다.
14. As a 매장 전용 PC 또는 직원 개인 기기 사용자, I want 브라우저를 다시 열어도 유효한 세션이 복원되어, 업무를 빠르게 재개할 수 있다.

## Implementation Decisions

- `Home`은 검색 중심의 고객 첫 화면을 뜻하며, 기존 소개 콘텐츠는 `Store Introduction`으로 구분한다.
- `/`은 검색 화면을 제공한다. `/books`와 `/search`는 검색으로 접근 가능한 기존 경로로 유지한다. 브랜드 소개를 위한 고객 경로와 탐색 이름은 `매장 소개`로 바꾼다.
- 고객용 로고의 일반 클릭은 `/`으로 이동한다. 로고의 3초 길게 누르기는 클릭 이동을 방해하지 않으며, 키보드로도 동등하게 접근 가능한 직원 진입 동작을 제공한다.
- 고객 앱 셸은 공개 직원 로그인 링크를 렌더링하지 않는다. 숨은 진입은 UI 노출을 줄이는 수단이며, Staff Account 승인 확인과 Supabase RLS를 대체하지 않는다.
- 직원 진입은 저장된 인증 세션을 조회한 뒤 Staff Account의 `approved` 상태와 역할을 확인한다. 승인된 Staff와 Admin은 대시보드로 보내고, 세션이 없거나 유효하지 않으면 로그인 화면을 보인다. 대기·비활성화 계정은 세션을 종료하고 운영 화면을 허용하지 않는다.
- Staff Shell에 로그아웃 동작을 제공한다. 로그아웃 뒤에는 인증 세션이 종료되고 보호된 Staff 경로가 운영 데이터를 표시하지 않는다.
- Supabase 기본 세션 영속성을 사용한다. 로그인 유지 대상은 매장 전용 PC와 직원 개인 기기이며, 고객과 공유하는 기기는 이번 범위에서 지원 정책을 정하지 않는다.
- 고객 모바일 개선은 기존 반응형 앱 셸과 고객 화면을 확장해 검색 입력, 결과 카드, 탐색, 도서 입고 신청의 수평 넘침과 주요 컨트롤 잘림을 없애는 데 집중한다. 직원 콘솔 전체의 모바일 재설계는 범위 밖이다.
- 검색 Home의 정적 메타데이터와 사이트맵은 루트 검색 목적에 맞게 갱신한다. 직원 화면은 계속 검색 색인 대상에서 제외한다.

## Testing Decisions

- 외부에서 보이는 탐색·권한·검색·폼 동작을 검증하고, 내부 상태 변수나 CSS 구현 방식은 직접 검증하지 않는다.
- 고객 앱 셸 테스트는 탐색 이름과 주소, 공개 직원 로그인 링크 부재, 로고의 일반 클릭 및 길게 누르기 진입을 검증한다.
- 앱 수준 라우팅 테스트는 `/`, `/books`, `/search`, 매장 소개의 콘텐츠와 기존 경로 호환을 검증한다.
- Staff 인증 흐름 테스트는 유효한 승인 세션의 자동 대시보드 이동, 세션 없음, 대기·비활성화 계정 차단, 로그아웃 후 보호 경로 차단을 검증한다.
- 고객 검색 및 도서 입고 신청 테스트는 기존 검색·결과·신청 테스트를 유지하고, 작은 뷰포트에서 주요 컨트롤과 결과 정보가 사용 가능한지를 검증한다.
- 프로덕션 빌드 후 모바일과 PC에서 루트 검색, 매장 소개, 숨은 직원 진입, 세션 복원과 로그아웃을 수동 검증한다.

## Out of Scope

- Staff 콘솔 전체의 모바일 정보 구조 재설계.
- 고객과 공유하는 기기의 세션 유지·자동 로그아웃 정책.
- 새로운 인증 제공자, 권한 모델, Supabase 스키마 또는 RLS 정책 변경.
- 직원 진입 동작을 보안 통제 수단으로 강화하는 작업.
- 검색 알고리즘, 도서 마스터·BookInventory 데이터 모델, 도서 입고 신청 필드 변경.

## Further Notes

- 이 명세는 2026-09-14 1차 중간 피드백과 `FR-STORE-001`, `FR-STORE-006`, `FR-AUTH-003`, `FR-AUTH-007`을 구현 기준으로 삼는다.
- 기존 브랜드 중심 Home에 관한 이전 기획은 이 명세의 검색 중심 Home과 매장 소개 결정으로 대체한다.
- 테스트 경계는 고객 앱 셸, Staff 접근 흐름, 고객 화면 반응형의 세 곳이다.
