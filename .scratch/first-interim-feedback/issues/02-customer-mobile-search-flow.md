# 02: 고객 탐색과 모바일 검색 흐름

**What to build:** 고객이 검색 중심 Home, 매장 소개, 즐길거리, 메뉴·요금, 이벤트·공지, 매장 안내를 일관된 탐색에서 사용할 수 있게 한다. 작은 화면에서도 도서 검색, 결과 확인, 도서 입고 신청을 가로 넘침이나 주요 조작의 잘림 없이 완료할 수 있게 한다.

**Blocked by:** 01: 검색 중심 Home과 매장 소개.

**Status:** complete

- [x] 데스크톱과 모바일 탐색이 검색 중심 Home과 매장 소개의 새 이름·주소를 제공한다.
- [x] 작은 화면에서 검색 입력, 도서명·보유 권수·서가 위치가 읽히고 조작할 수 있다.
- [x] 화면 키보드가 열린 모바일 환경에서도 검색과 도서 입고 신청의 핵심 동작을 완료할 수 있다.
- [x] 고객 화면의 주요 흐름에서 가로 스크롤과 컨트롤 잘림이 없다.
- [x] 고객 탐색·검색·신청의 외부 행동과 모바일 수동 검증을 통과한다.

## Validation

- Chrome iPhone 12 에뮬레이션(390px)에서 검색 입력에 포커스한 뒤 `3월의 라이온`을 검색해 도서명, `1~17권`, `책장 1번`을 확인했다. 문서 폭은 390px으로 뷰포트와 같았다.
- 같은 환경에서 결과 없음 검색어 `없는 책`으로 도서 입고 신청으로 이동했다. 제목이 전달된 신청 폼과 제출 버튼을 확인했고, 문서 폭은 390px으로 뷰포트와 같았다.
- Chrome 320px·390px 뷰포트에서 검색 Home, 매장 소개, 도서 입고 신청 화면 모두 문서 폭과 뷰포트 폭이 같았다. 320px에서 헤더 보조 동작이 가로 넘침의 원인이었으며 이를 숨겨 해결했다.
- 전체 자동화 테스트와 프로덕션 빌드를 통과했다.
