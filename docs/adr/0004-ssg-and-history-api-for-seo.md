# 4. SEO를 위한 SSG 및 History API 라우팅 도입

Date: 2026-09-11

## Status

Accepted

## Context

초기 카툰플러스 클라이언트는 Hash 기반 자체 라우터(`window.location.hash`)를 사용하는 React SPA 환경이었습니다. 이 구조는 정적 호스팅(Cloudflare Pages) 환경 배포가 매우 간편하지만, 구글이나 네이버 같은 검색엔진과 카카오톡 등의 스크랩 봇이 개별 서브 페이지(`/books`, `/menu` 등)를 제대로 색인하지 못하는 문제(SEO 한계)가 있었습니다.

이를 해결하기 위해 서버사이드 렌더링(SSR) 또는 정적 사이트 생성(SSG) 도입이 필요했습니다. 하지만 현재 운영 환경은 Cloudflare Pages(무료 티어 기반의 정적 호스팅)를 사용 중이므로, 별도의 Node.js 서버 런타임이 필요한 SSR을 도입할 경우 운영 요금 및 관리 비용이 크게 증가할 수 있었습니다.

## Decision

* **SSG (Static Site Generation)**: 런타임 서버 비용이 0원인 정적 호스팅의 장점을 유지하기 위해, SSR 대신 빌드 타임에 HTML 파일을 생성하는 SSG 방식을 채택합니다.
  * 복잡한 프레임워크(Next.js, Vike 등) 대신, Vite 빌드 시점에 메인 템플릿을 복사하여 각 카테고리(라우트)별로 `index.html`을 생성하고 `<title>`, `<meta>` 정보를 주입하는 자체 빌드 스크립트를 사용합니다. (오버엔지니어링 방지)
* **History API 라우팅 전환**: 해시 기반 라우터를 `react-router-dom`을 활용한 History API 기반으로 전환하여 정상적인 URL 체계를 갖춥니다.
* **부분적 동적 데이터 (카테고리 레벨)**: 수천 권의 개별 도서에 대한 HTML 생성이 아니라, `도서 검색`, `메뉴`, `이벤트` 등 주요 진입점(Entry) 라우트에 한해서만 HTML을 정적 생성합니다.

## Consequences

* **운영 비용 제로**: 기존과 동일한 Cloudflare Pages 정적 호스팅을 유지하므로 추가 서버 유지비가 발생하지 않습니다. (개발/포트폴리오 관점에서도 최적화된 아키텍처 결정을 입증할 수 있습니다.)
* **SEO 완벽 대응**: 주요 페이지 링크를 카카오톡에 공유하거나 구글에서 검색할 때, 해당 페이지에 맞는 고유한 메타 정보와 제목이 정상적으로 노출됩니다.
* **라우터 표준화**: `react-router-dom`으로 전환되어 컴포넌트 구조가 깔끔해지고 유지보수가 용이해집니다.
* 빌드 파이프라인(Vite config 또는 자체 스크립트)이 약간 복잡해지며, Cloudflare Pages 설정 파일(`_routes.json` 또는 Cloudflare의 SPA 폴백 규칙)을 이에 맞게 구성해야 합니다.
